# GM-IX 上位机数据协议调研与讨论（V0.1）

> 目的：确定厂商上位机中**可复用的数据协议**，作为自研上位机平台的数据契约基础。
> 调研对象：`C:\Program Files\HRAS_9000\application\HRAS_9000.exe` 与 `references/HRAS9000`。
> 结论性质：调研与方案讨论，未进入实现。

---

## 1. 调研结论

### 1.1 厂商上位机的实际结构

`HRAS_9000.exe` 是 **MATLAB Compiler R2023a standalone** 程序（readme 明确要求 MATLAB Runtime R2023a）。其内嵌 CTF 中包含：

```text
fsroot/HRAS_9000/ADC/QT2144_Dll/QT_Board.dll
fsroot/HRAS_9000/ADC/QT2144_Dll/QT_Board.h
fsroot/HRAS_9000/ADC/QT2144_Dll/QT_Board.lib
fsroot/HRAS_9000/ADC/QT2144_Dll/QT_Board_MATLAB.h
fsroot/HRAS_9000/ADC/QT2144_Dll/QT_Board_Project.h
fsroot/HRAS_9000/ADC/QT2144_Dll/QT_Board_MATLAB_proto.m
fsroot/HRAS_9000/ADC/QT2144_Dll/config/*.json
fsroot/HRAS_9000/OFDR_process_segments.m
fsroot/HRAS_9000/OFDR_calibrate_il.m
fsroot/HRAS_9000/OFDR_baseline_il.m
fsroot/HRAS_9000/OFDR_summarize_metrics.m
fsroot/HRAS_9000/HRAS9000.mlapp
```

其中：

- `QT_Board.h` / `QT_Board_MATLAB.h` / `QT_Board_Project.h` 是**明文 C 头文件**，可读；
- `.m` 文件是 **MATLAB p-code 加密字节**（文件头 `V2MCC8000...`），不能直接得到算法源码；
- `config/InitUI.json` 也是加密/混淆内容，其他 config JSON 为明文；
- 程序直接通过 MATLAB thunk 调用 `QT_Board.dll`，**没有面向第三方应用的独立 TCP/文件数据协议**。

### 1.2 因此“可复用的数据协议”是什么

厂商上位机并没有对外暴露一个“数据协议”；它复用厂商板卡 SDK 的 C API，数据只在进程内流转：

```text
QT_Board.dll（板卡 API）
   → 原始 ADC buffer（unsigned char*）
   → MATLAB OFDR 处理（p-code）
   → App UI / 报告
```

所以我们要确定的不是“如何模仿厂商的私有协议”，而是：

1. **设备访问契约**：继续用 `qt_acq`（已实测）或 `QT_Board`（能力更全、无头文件也可从内嵌 CTF 取得）；
2. **平台内部数据契约**：定义采集帧、处理结果、事件指标、会话与校准元数据；
3. **持久化格式**：原始波形、处理数组、事件表、历史索引分别怎么存。

### 1.3 可复用资产清单

| 资产 | 位置 | 可复用性 |
|---|---|---|
| `QT_Board.h` | 厂商 CTF 内嵌 | 高：完整设备 API、参数、取数函数 |
| `QT_Board_Project.h` | 厂商 CTF 内嵌 | 中：项目专用扩展（触发延时、采集模式等） |
| `QT_Board_MATLAB.h` | 厂商 CTF 内嵌 | 中：MATLAB 封装，可参考调用顺序 |
| `config/*.json` | 厂商 CTF 内嵌 | 高：Interface / AFE / Range / FunctionalConfiguration |
| `qt_acq` 9 函数 | `references/qt2144-rs` | 高：已实测，适合 MVP |
| `ofdr.dll` / `detect.dll` | `references` | 高：已实测，处理与指标 |
| `.m` OFDR 算法 | 厂商 CTF | **不可复用**：p-code 加密 |

## 2. 建议的数据协议分层

不要把所有东西塞进一个“大包”。建议分四层：

```text
L0 设备访问协议    qt_acq / QT_Board C ABI
L1 采集帧 ScanFrame  原始 int16 + 采集配置 + 质量标记
L2 处理结果 OfdrResult  dist/freq/ps + 处理配置
L3 事件指标 EventMetrics 峰/段/事件/IL/RL + 检测配置
L4 会话与校准 SessionMeta + Calibration
```

### 2.1 L0 设备访问协议

- MVP 继续用 `qt_acq`：
  - `open/configure/start/read/stop/close`；
  - 数据为 int16 小端、4 通道交织；
  - 长度 `rate × ms × 8000 × segs`。
- 若要更细的控制（AFE、量程、触发模式、FIFO、流模式、code→voltage），再直接用 `QT_Board`：
  - `QT_BoardSetupRecSamplerate`
  - `QT_BoardSetupModeRecStdSingle/Multi`
  - `QT_BoardSetupTrigRecSoftware/External`
  - `QT_BoardSetupRecGetData`
  - `QT_BoardGetFIFODataBuffer`
  - `QT_BoardConvertCodeValueToVoltageValue`
  - `QT_BoardSetStreamRecGetSTDData / SetStreamRecGetFIFOData`

**MVP 不建议直接替换成 QT_Board**：qt_acq 已验证；QT_Board 384 个导出、无正式维护文档，风险高。

### 2.2 L1 采集帧 ScanFrame（内存模型）

建议字段：

| 分类 | 字段 | 说明 |
|---|---|---|
| 标识 | `scanId` | GUID/雪花 ID |
| 标识 | `sequence` | 单会话内递增 |
| 时间 | `capturedAtUtc` | 采集完成时间 |
| 设备 | `deviceId` / `deviceName` | GM-IX / 序列号 |
| 设备 | `sdkVersion` / `firmware` | 追溯 |
| 参数 | `sampleRateHz` | 10/50/125/250 MHz |
| 参数 | `acqTimeMs` | 采集时长 |
| 参数 | `segCount` | MVP 固定 1 |
| 参数 | `triggerMode` / `triggerDelayMs` | 软件触发为 0 |
| 参数 | `channelMap` | P=0, S=1, A=2, ch3 忽略 |
| 参数 | `configHash` | 配置快照哈希 |
| 数据 | `frameCount` | `rate × ms × 1000` |
| 数据 | `bufferBytes` | `frameCount × 8` |
| 数据 | `raw` | int16 LE、4 通道交织 |
| 质量 | `shortRead` / `saturatedChannels` / `droppedFrames` | 质量标记 |
| 校验 | `checksum` | CRC32/SHA256 |

### 2.3 L2 处理结果 OfdrResult

| 字段 | 类型 | 说明 |
|---|---|---|
| `scanId` | string | 关联采集帧 |
| `fsHz` | double | `rate_mhz × 1e6` |
| `distScale` | double | 距离校准系数 |
| `inputLength` | int64 | N |
| `outputLength` | int64 | `N/2 + 1` |
| `dist` | double[] | m，严格递增、等间距 |
| `freq` | double[] | Hz，`k×fs/N` |
| `ps` | double[] | 线性幅值，非 dB |
| `ofdrVersion` | string | 处理库版本/哈希 |
| `distStep` | double | 单次内均匀步长 |
| `quality` | flags | 单调性、长度、异常 |

存储时数组用二进制（`.f64` 或内存映射），元数据用 JSON，不要用 CSV 存百万点数组。

### 2.4 L3 事件指标 EventMetrics

| 字段 | 类型 | 说明 |
|---|---|---|
| `scanId` | string | 关联 |
| `detectConfig` | object | 8 个默认参数 |
| `nPeaks/nSegments/nEvents` | int | 数量 |
| `peakLoc/Height/Base/Prominence` | double[] | 峰 |
| `segStart/End/NoiseFloor` | int64[]/double[] | 基线段 |
| `eventLoc/Peak/IL/RL/BaseBefore/BaseAfter` | double[] | 事件 |
| `zeroPeakIncluded` | bool | 是否包含零距峰 |
| `calibrationId` | string | 关联校准快照 |

体积很小，适合 JSON/CSV/数据库。

### 2.5 L4 会话与校准

| 字段 | 说明 |
|---|---|---|
| 设备信息 | 名称 GM-IX、序列号、固件、SDK |
| 光路/通道 | P/S/A 映射、ch3 忽略 |
| 配置快照 | Interface/AFE/Range/FunctionalConfiguration |
| 距离校准 | `dist_scale`、标定件、标定时间 |
| 绝对电平校准 | PSD anchor `K(f)`、IL 斜率/截距（第二阶段） |
| 操作员/工位/备注 | 业务追溯 |

## 3. 格式与数据包定义

### 3.1 结论：MVP 不需要自定义网络数据包

设备侧的数据包由 `QT_Board_Net.dll` 内部处理，厂商没有公开；我们不应重新发明。

我们需要的只是**内部数据契约**：

- 进程内：强类型对象（C# record/struct）；
- 跨进程/落盘：`二进制数组 + JSON 元数据`；
- 事件/指标：JSON 或 CSV。

### 3.2 如需二进制封装（文件或 IPC）

建议统一头：

```c
struct GmixPacketHeader {
    uint32 magic;        // 'GMIX'
    uint16 version;      // 1
    uint16 type;         // 1=raw, 2=ofdr, 3=events
    uint32 headerBytes;  // sizeof(header)
    uint64 sequence;
    int64  timestampNs;  // UTC
    uint32 payloadBytes;
    uint32 crc32;
    uint16 flags;
    uint16 reserved;
};
```

负载：

- raw：`ScanFrame` 元数据 + int16 数据；
- ofdr：`fs/distScale/N` + dist/freq/ps 三个 double 数组；
- events：峰/段/事件数组。

MVP 可以只实现 raw 文件 + JSON sidecar，不必上二进制包格式。

## 4. 传输与存储：文件、内存还是数据库？

| 场景 | 建议 | 原因 |
|---|---|---|
| 设备 → 采集进程 | SDK 调用（内部 TCP） | 不暴露私有协议 |
| 采集 → 处理/UI（实时） | 内存 + 有界队列/共享内存 | 避免磁盘成为实时路径瓶颈 |
| 原始波形归档 | **文件**：`.bin` + `.json` | 单次可达 100 MB，适合顺序读写 |
| OFDR 数组 | **文件**：`.f64` + `.json` | 百万点级，CSV 过大 |
| 事件/指标 | **文件**：JSON/CSV | 体积小，便于交换 |
| 历史检索/统计 | **数据库（可选，第二阶段）** | 只存索引/元数据，不存波形 |
| 校准数据 | 文件 + 数据库索引 | 需版本追溯 |

不建议把原始波形放进数据库；100 MB/次的 BLOB 会拖垮查询与备份。数据库只做“测量记录索引 + 关键指标 + 文件路径”。

项目当前禁止引入 NuGet，若后续使用 SQLite 需先走 ADR/依赖例外；MVP 用文件即可。

## 7. 已确认决策（2026-11-04）

| 项 | 决策 |
|---|---|
| 上位机技术栈 | **.NET / WPF** |
| 存储 | **文件 + JSON**（MVP 不上数据库） |
| 数据范围 | **仅相对测量**：单次扫频、距离曲线、事件表、相对 IL/RL |
| 设备访问 | MVP 继续用已验证的 `qt_acq` C ABI；`QT_Board` 直调留到需要 AFE/量程/触发细控时 |
| 通道映射 | 固定 `ch0=P、ch1=S、ch2=A`，`ch3` 不使用 |
| 多段/外触发 | 不做 |
| 绝对 RL / dBm | 第二阶段，配合 PSD 基准标定 |

### 7.1 MVP 文件布局

```text
GMIX_DATA/
└─ <scanId>/                    # 例：20261104_153000_0001
   ├─ scan.json                 # ScanFrame 元数据
   ├─ raw.bin                   # int16 LE、4 通道交织、每帧 8 字节
   ├─ ofdr.json                 # OfdrResult 元数据（fs/distScale/N/Lout）
   ├─ dist.f64                  # double[]，little-endian
   ├─ freq.f64
   ├─ ps.f64
   ├─ events.json               # EventMetrics
   └─ events.csv                # 导出用
```

约定：

- 所有 JSON 带 `schemaVersion: "1.0"`；
- `scanId` 全局唯一，建议 `yyyyMMdd_HHmmss_NNNN`；
- `raw.bin` 长度必须等于 `rate × ms × 8000`（MVP 单段）；
- `dist/freq/ps` 长度必须等于 `N/2 + 1`；
- 相对 RL 在 JSON/UI 中标注 `unit: "dB_rel"`，不写 `dBm`；
- 原始波形与数组不落数据库；若后续需要检索，再加 SQLite 索引表，只存 `scanId`、时间、设备、路径、关键指标。
