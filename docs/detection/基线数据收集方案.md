# 基线数据收集方案（TBD-D05a / TBD-D05b）

> **性质**：方法方案，不含实测数值。用于解锁 SRS v0.4 §8 的 `TBD-D05a`（IL/RL 参考范围与展示口径）与 `TBD-D05b`（峰位置期望窗口与 `peak_unexpected` 规则）。
> **边界**：软件只导入、校验、使用与留痕基线，**不生成、不修改、不审批基线**（SRS `FR-065`）。本方案由硬件/工艺团队执行采集与评审，软件团队提供数据口径与导入校验。
> **关联**：[SRS v0.4 §4.5/§4.6/§4.7](SRS_检测平台_v0.4.md)、[L2 GM-IX 数据与处理规范 §4/§5](../contracts/GM-IX_数据与处理规范_v1.0.md)、[OCS 协议实测报告](OCS_协议实测报告_2026-11-11.md)。

## 1. 目标与产出

| TBD | 需要回答的问题 | 本方案产出 |
|---|---|---|
| TBD-D05a | 每条路径的 IL/RL 参考范围怎么定？展示用绝对范围、基线差值还是两者？超范围如何提示？ | 采集口径、统计方法、参考范围候选规则、`out_of_reference` 触发规则 |
| TBD-D05b | 每条路径的期望峰位置窗口多宽？何时置 `peak_unexpected`？ | 峰位置统计方法、窗口公式、峰选择规则、提示触发规则 |

最终产出是一份经审批的 `baseline.json`（字段见 SRS §4.7）与对应的评审记录；本方案只定义"怎么得到这些数"，不预设数值。

## 2. 前置条件

| 项 | 要求 |
|---|---|
| DUT | golden DUT（已知良品）至少 1 台；有条件时增加 2~3 台同型号良品用于评估个体差异 |
| OFDR | LGA50-D 已完成标定，`configHash` 可读取；批次内 `calibrationStatus = calibrated` |
| OCS | 1×8 与 8×8 固件版本、SN 已登记；串口参数按 [实测报告 §10](OCS_协议实测报告_2026-11-11.md) 配置 |
| 光路 | 测试光纤/夹具固定，长度已知并记录；1×8↔8×8 光口映射已按 TBD-D03a / TBD-O08 核实 |
| 路径计划 | 固定版本，64 条 `IN i → OUT j`；每路径扫描次数 N 固定且 N ≥ 3 |
| 环境 | 同一工位、同一操作员、同一批次参数；记录环境温度（可选但建议） |
| 软件 | 检测平台能按 SRS §6.6 产出批次目录与 `detection.json`；未就绪前不得用其他工具拼数据 |

数据必须来自**同一配置快照**：`configHash`、`ofdrConfigHash`、路径计划版本、扫描参数在全部样本中一致。任何一项变化，样本不得混入同一基线。

## 3. 采集流程

1. **固定配置**：锁定 OFDR 扫描参数、OCS 串口参数、路径计划与 N；记录 `configHash`、`ofdrConfigHash`、路径计划版本。
2. **逐台 DUT 采集**：每台 golden DUT 连续执行 **3 个完整批次**（64 路径 × N 次扫描），批次之间不修改任何参数。
3. **保持光路不变**：同一台 DUT 的 3 个批次使用同一夹具与同一光纤；批次间允许重新插拔时，必须记录并在统计时单独标记。
4. **采集原始证据**：保留 `group.json`、`Rxxx/summary.json`、`AVG/summary.json`、`detection.json`；原始曲线是否保留按 SRS `FR-089` 策略执行。
5. **登记异常**：扫描失败、串口重试、回读不一致、标定失效等逐条登记，不删除、不修正原始数据。
6. **冻结数据集**：采集完成后生成数据集清单（批次 ID、DUT SN、`configHash`、时间、文件哈希），交由评审；冻结后不得再追加或挑选样本。

## 4. 记录字段

以 `detection.json` 的 `paths[]` 与 L2 `summary.json` 为准，逐路径导出以下列（与 SRS §6.5 检测 CSV 对齐）：

```text
batchId, pathId, in, out, groupId, avgScanId, scanIds,
averageCount, validCount, connectivity,
ilDb, rlDb, calibrationStatus, metricSource,
peakPresent, peakPositionM, peakNo, zeroPeakExcluded,
configHash, ofdrConfigHash, baselineId, baselineVersion,
operator, station, startedAt, endedAt
```

补充记录（不进入检测 CSV，单独随数据集提交）：DUT SN、固件版本、夹具编号、光纤长度、环境温度、批次间是否重新插拔。

口径要求：

- `ilDb` / `rlDb` 取 `AVG/summary.json`；N=1 时取 `R001/summary.json`。
- 距离与峰位置一律用**米**；不得用 UI 的 mm 值回流。
- 缺失值保持空，不得写 `0`、`NaN` 或估计值。
- `connectivity ≠ ok` 的路径不参与该路径的范围统计，但必须保留在数据集中并计数。
- `calibrationStatus ≠ calibrated` 的批次整批不参与统计。

## 5. 统计方法

### 5.1 单路径统计量

对每条路径、每个指标（IL、RL、峰位置）分别计算：

| 统计量 | 用途 |
|---|---|
| n | 有效样本数（跨批次汇总） |
| median | 基线中心值 |
| MAD | 稳健离散度：`median(|x - median|)` |
| mean / sd | 常规均值与标准差（用于对照） |
| min / max | 观测极值 |
| p1 / p99 | 绝对范围候选边界 |
| 批内 sd | 重复性（同一 DUT、同一路径、同批次内 N 次） |
| 批间 sd | 稳定性（同 DUT、跨 3 个批次） |

### 5.2 异常值处理

- 稳健 z 分数：`z = 0.6745 × (x - median) / MAD`；`|z| > 3.5` 记为疑似异常。
- 疑似异常只**标记**，不自动删除；由评审确认是测量故障还是 DUT 真实差异。
- 被确认的测量故障样本从统计中剔除，但保留在数据集与异常清单中，注明剔除原因。
- 有效样本不足（任一指标 `n` 少于评审确认的最小样本量）时，该路径标记"样本不足"，不得发布参考范围。

### 5.3 重复性优先

参考范围与峰窗口的宽度必须由**重复性**约束，而不是先拍一个容差：

- 单次重复性：同一路径 N 次采样的批内 sd。
- 批次重复性：同 DUT 3 个批次的批间 sd。
- 取两者较大值作为该路径的 `repeatSd`，避免把批次漂移漏掉。

## 6. TBD-D05a：IL/RL 参考范围与展示口径

### 6.1 双层口径（建议）

| 层 | 定义 | 用途 |
|---|---|---|
| 绝对范围 | 该路径 `median ± k × repeatSd`，或评审确认的 `[p1, p99]` | 判断单次测量是否落在该路径的正常区间 |
| 基线差值 | `measured - baselineMedian` | 判断相对 golden DUT 的偏移，识别"绝对值正常但路径接错"的情况 |

`k` 由评审确定（候选 3 或 3.5），写入基线文件；不得在代码中写死。

### 6.2 展示与提示规则

- UI 展示：测量值、基线中心值、差值、参考范围；不显示 Pass/Fail。
- `out_of_reference` 触发条件（两者满足其一）：
  1. 测量值落在绝对范围外；
  2. 差值绝对值超过评审确认的差值容差。
- 不触发的情况：
  - 无适用基线 → 置 `baseline_missing`，不评估 `out_of_reference`（`FR-063`）；
  - `calibrationStatus ≠ calibrated` → 置 `calibration_invalid`，IL/RL 为 `null`，不评估；
  - `connectivity ≠ ok` 或指标为 `null` → 不评估。
- 同一路径 IL、RL 分别判断，可同时触发；与其它关注提示并存，不互相覆盖。
- 提示只提示，不改变测量值、不拦截批次（`FR-052`）。

### 6.3 评审需确认的参数

| 参数 | 说明 | 评审结论 |
|---|---|---|
| `k` 或分位边界 | 绝对范围宽度 | 待填 |
| IL 差值容差 | 相对基线的允许偏移 | 待填 |
| RL 差值容差 | 同上 | 待填 |
| 最小样本量 | 低于则该路径不发布范围 | 待填 |
| RL 符号处理 | 沿用 L2，不取负；范围按带符号 dB 表达 | 固定 |

## 7. TBD-D05b：峰位置窗口与 `peak_unexpected`

### 7.1 期望峰位置

- 对每条路径，取 golden DUT 全部有效样本的峰位置 median 作为 `expectedPeakM`。
- 若路径存在多个候选峰，先按 §7.2 选定主峰，再统计其位置。

### 7.2 主峰选择

1. 按 L2 规则排除零距峰：位置 `< analysisRange.startM` 记为 `zeroPeak`，不参与峰编号与窗口判断。
2. 在分析区间内取峰值最高且 `zeroPeak=false` 的峰为主峰，记录 `peakNo`。
3. 若最高峰不唯一，取位置最靠近 `expectedPeakM` 的峰；仍不唯一时置 `peak_unexpected` 并记录原始候选列表供人工复核。

### 7.3 窗口公式（建议）

```text
windowHalfWidth = max(3 × repeatSdPosition, fixtureLengthUncertainty, distanceResolution)
window = [expectedPeakM - windowHalfWidth, expectedPeakM + windowHalfWidth]
```

- `repeatSdPosition`：该路径峰位置在重复测量中的标准差，取批内/批间较大值。
- `fixtureLengthUncertainty`：测试光纤/夹具长度公差，由硬件团队给出。
- `distanceResolution`：OFDR 距离轴分辨率（来自扫描参数）。
- 三项都必须是实测或规格值，不得用经验常数替代。

### 7.4 触发规则

| 条件 | 结果 |
|---|---|
| `connectivity = ok` 且主峰在窗口内 | 不置 `peak_unexpected` |
| `connectivity = ok` 且主峰在窗口外 | 置 `peak_unexpected`（警告） |
| `connectivity = noPeak` | 置 `no_peak`，不置 `peak_unexpected` |
| `connectivity = invalidFrame / notComputed` | 不评估峰窗口 |
| 无适用基线 | 置 `baseline_missing`，不评估 `peak_unexpected` |

### 7.5 评审需确认的参数

| 参数 | 说明 | 评审结论 |
|---|---|---|
| `repeatSdPosition` 来源 | 批内/批间取大 | 待填 |
| 夹具长度公差 | 硬件团队提供 | 待填 |
| 多峰并列处理 | 按 §7.2 | 待评审 |
| 窗口最小宽度 | 防止窗口过窄导致误报 | 待填 |

## 8. 评审、发布与导入

1. **评审组**：硬件/工艺、软件、产线质量各一名；评审数据集、统计报告、范围与窗口。
2. **签署**：填写 `approvedBy`、`approvedAt`（UTC），生成 `baseline.json`；`applicable` 至少含 `dutModel`。
3. **版本**：`version` 追加递增，不覆盖历史版本（`FR-061`）。
4. **导入校验**：软件校验 schema、必填字段、版本递增；`dutModel` + 可选 `dutSerial` 匹配到多条时要求人工确认（`FR-062`）。
5. **留痕**：批次记录 `baselineId` 与 `version`；历史批次始终能解析其引用版本。
6. **变更**：任何范围/窗口调整都生成新版本，不复用旧 `baselineId`。

## 10. 禁止事项

- 禁止软件提供"从测量结果自动生成基线"的入口（`FR-065`）。
- 禁止用单批次、单次扫描或挑选过的样本生成基线。
- 禁止用 `0`、均值填充或估计值替代缺失值。
- 禁止跨 `configHash` / `ofdrConfigHash` / 路径计划版本混用样本。
- 禁止在代码中写死范围、窗口、容差或最小样本量。
- 禁止事后修改已发布基线的数值；变更只能追加新版本。
