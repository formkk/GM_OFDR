# OCS 控制协议分析（1×8 / 8×8）

> **来源**：`references/ocs/控制协议1X8(2).docx`、`references/ocs/控制协议8X8(2).docx`（厂商原始文档）。
> **状态**：基于文档提取，**尚未实机核对**。文中“文档明确”为原文事实；文档未写、需要实测的项统一登记为 `TBD-Oxx`。
> **关联**：本文部分关闭 `TBD-D02`（OCS 控制接口与命令集）；`TBD-D03`（1×8 与 8×8 关系）、`TBD-D04`（切换稳定时间与超时）仍需硬件确认。

## 1. 结论摘要

- 两型 OCS 均为 **RS232、9600 8N1、ASCII 字符帧**，帧格式为 `<` + 命令 + `>`。
- **1×8**：单输入 `COM`，8 选 1；命令集小，只有单路设置与当前通道查询。
- **8×8**：8×8 矩阵；支持单路设置、整矩阵一次性设置、单路查询与全量查询。
- 8×8 整矩阵设置有一条硬约束：**非 0 输出不可重复**，否则设备返回 `<ER_SetValue>`。
- 两型共有命令：`<IDN?>`、`<SN?>`、`<RST>`、`<SETSW...>`、`<QURSW...>`。
- 关键未知项：切换稳定时间、回包超时、是否需要 CR/LF、单路命令是否也强制输出唯一、错误码全集、光口物理映射、1×8 与 8×8 的级联方式。

## 4. 1×8 命令集

| 命令 | 成功返回 | 语义 |
|---|---|---|
| `<IDN?>` | `<GK,GK-OSW-1X8-SM-1315-FU-R-01,2026-08-03,VERSION1.0>` | 查询设备信息 |
| `<SN?>` | `<26080301>` | 查询设备编号 |
| `<RST>` | `<OK>` | 设备复位 |
| `<SETSW1-yy>` | `<1-yy>` | 设置 `COM` → `CHyy`；`yy=0` 断开，`1~8` 对应 CH1~CH8 |
| `<QURSW?>` | `<SW1-yy>` | 查询当前通道 |

示例：

```text
发送：<SETSW1-03>
返回：<1-03>          # COM → CH3
发送：<QURSW?>
返回：<SW1-03>
```

说明：

- 输入通道 `x` 固定为 `1`（COM），文档没有提供其他输入。
- 同一时刻只有一个输出有效；`yy=0` 表示断开。
- 文档未提供逐通道查询，也没有整矩阵设置命令。
- 断开命令的返回格式按两位推断为 `<1-00>`，**待实测确认**（TBD-O02）。

## 5. 8×8 命令集

| 命令 | 成功返回 | 语义 |
|---|---|---|
| `<IDN?>` | `<GK,GK-OSW-8X8-SM-1315-FU-R-01,2026-08-03,VERSION1.0>` | 查询设备信息 |
| `<SN?>` | `<26080302>` | 查询设备编号 |
| `<RST>` | `<OK>` | 设备复位 |
| `<SETSWx-yy>` | `<x-yy>` | 设置 `INx` → `OUTyy`；`x=1~8`，`yy=0~8` |
| `<SETSWabcdefgh>` | `<OK>` | 一次性设置 8 路；`a~h` 对应 `IN1~IN8` 的输出，取值 `0~8` |
| `<QURSWx?>` | `<SWx-yy>` | 查询第 `x` 路当前输出 |
| `<QURSW?>` | `<SW0a_0b_0c_0d_0e_0f_0g_0h>` | 查询全部 8 路 |
| 错误 | `<ERROR>` / `<ER_SetValue>` | 非法命令 / 整矩阵设置冲突 |

### 5.1 单路设置

```text
发送：<SETSW1-02>
返回：<1-02>          # IN1 → OUT2
发送：<QURSW4?>
返回：<SW4-02>        # IN4 → OUT2
```

### 5.2 整矩阵设置

`<SETSWabcdefgh>` 中：

- `a` 对应 `IN1` 的输出，`b` 对应 `IN2`，依此类推，`h` 对应 `IN8`。
- 每个取值为 `0~8`；`0` 表示该路断开。
- 非 0 值不可重复，否则返回 `<ER_SetValue>`。

示例：

```text
发送：<SETSW15632487>
返回：<OK>
含义：IN1→OUT1, IN2→OUT5, IN3→OUT6, IN4→OUT3,
      IN5→OUT2, IN6→OUT4, IN7→OUT8, IN8→OUT7

发送：<SETSW23340056>
返回：<ER_SetValue>    # 输出 3 重复（IN2、IN3 都指向 OUT3）
```

### 5.3 全量查询

返回格式为 `SW` + 8 组两位数字，组间用 `_` 分隔：

```text
<SW0a_0b_0c_0d_0e_0f_0g_0h>
```

示例：

```text
<SW03_00_01_02_04_00_06_05>
```

含义：`IN1→OUT3`、`IN2` 断开、`IN3→OUT1`、`IN4→OUT2`、`IN5→OUT4`、`IN6` 断开、`IN7→OUT6`、`IN8→OUT5`。

## 6. 1×8 与 8×8 差异

| 维度 | 1×8 | 8×8 |
|---|---|---|
| 拓扑 | 单输入 COM，8 选 1 | 8 输入 × 8 输出矩阵 |
| 输入通道 | 固定 `x=1` | `x=1~8` |
| 输出通道 | `yy=0~8` | `yy=0~8` |
| 单路设置 | `<SETSW1-yy>` | `<SETSWx-yy>` |
| 整矩阵设置 | 不支持 | `<SETSWabcdefgh>` |
| 单路查询 | 不支持 | `<QURSWx?>` |
| 全量查询 | `<QURSW?>` → `<SW1-yy>` | `<QURSW?>` → `<SW0a_..._0h>` |
| 输出唯一性 | 天然唯一（单输入） | 整矩阵命令强制非 0 输出唯一；单路命令是否也强制，**待实测**（TBD-O04） |
| 错误码 | `<ERROR>` | `<ERROR>`、`<ER_SetValue>` |

## 7. 上位机实现约束

1. **命令串行化**：一次只发一条命令，收到完整回包后再发下一条；文档未说明是否支持流水线，未实测前不要并发。
2. **参数校验在发送前完成**：
   - 1×8：`x` 必须为 `1`，`yy` 为 `0~8`。
   - 8×8：`x` 为 `1~8`，`yy` 为 `0~8`。
   - 8×8 整矩阵：先校验非 0 输出唯一，再发送，避免依赖设备报错。
3. **回包解析按定界符**：读取到 `>` 结束；容忍 `<SWx-yy >` 这类尾随空格；不要按行读取。
4. **设置后回读**：通道切换后建议用 `QURSW` / `QURSWx?` 回读确认，再触发 OFDR 扫描；回读不一致按设备错误处理。
5. **超时与重试不写死猜测值**：文档未给出回包超时；先按实测 p99 加余量确定，登记 TBD-O02。重试次数与退避策略同样由实测确定。
6. **错误分类**：
   - 传输错误（串口打不开、写失败、读超时）；
   - 协议错误（回包不以 `<` 开头、不以 `>` 结尾、长度异常）；
   - 设备错误（`<ERROR>`、`<ER_SetValue>`）。
   三类错误映射为不同 UI 消息，禁止静默吞掉。
7. **状态机**：启动先查询当前状态，不默认执行 `<RST>`；复位会改变光路，必须由明确操作触发。
8. **日志**：记录原始 TX/RX（ASCII 与十六进制）、时间戳、命令序号、耗时；便于复现时序问题。

## 9. 所缺资料能否通过测试取得

结论：**协议行为与时序大部分可以通过测试取得；光学指标需要校准设备；寿命、内部设计与固件差异只能由厂商提供。**

| 类别 | 能否测试取得 | 说明 |
|---|---|---|
| 命令回包、超时、重试、幂等、CR/LF、回显 | **可以** | 串口抓包 + 重复命令统计即可 |
| 切换稳定时间、上电/复位状态 | **可以** | 需要光功率计或光电探测器 + 示波器；仅靠串口无法测 |
| 单路命令的输出唯一性 | **可以** | 构造冲突路径并回读 |
| 错误码全集 | **可以（有限）** | 只能覆盖可构造的非法输入；未公开错误码可能遗漏 |
| 串口引脚/线序 | **可以** | 万用表通断；但建议厂商确认，避免接错 |
| 插入损耗、回波损耗、串扰、波长范围 | **部分可以** | 需要校准过的光源、功率计、ORL；绝对精度依赖校准 |
| 1×8 与 8×8 级联映射 | **可以** | 逐路切换 + OFDR 峰值/光功率验证 |
| 切换寿命、MTBF、内部光学设计 | **不可以** | 只能由厂商提供或做加速寿命试验（成本高） |
| 固件版本差异、未公开命令 | **不可以** | 需厂商文档或固件说明 |

### 9.1 建议的测试顺序

1. **串口基线**：USB-RS232 + 串口监听，确认 9600 8N1、帧格式、是否有回显/CRLF。
2. **命令矩阵**：`IDN?`、`SN?`、`QURSW?`、合法/非法 `SETSW`，每类 N=100，统计 p50/p95/p99/max。
3. **状态与约束**：逐路设置并回读；测试 `0` 断开、越界、重复输出、复位、断电重启。
4. **切换时间**：光路接光功率计或光电探测器，记录“命令发出 → 光功率稳定在容差内”的时间；1×8 与 8×8 分开测，各 100 次。
5. **级联映射**：1×8 COM 接 8×8 输入，逐路打通，记录 64 条路径的 IL 与 OFDR 峰值位置。
6. **错误码扫描**：缺 `>`、多余字符、大小写、空格、未知命令、越界参数；记录回包或超时。
7. **长稳**：1k/10k 次连续切换，统计错误、超时、回读不一致。
8. **光学指标**：校准功率计测 IL/RL，宽带源 + 功率计测串扰；或直接向厂商索取规格书。

### 9.2 测试前置条件

- USB-RS232 适配器与对应线序；
- 串口监听工具（能同时看 TX/RX 原始字节）；
- 光功率计、稳定光源、ORL（或厂商校准数据）；
- 光电探测器 + 示波器（测切换瞬态）；
- OFDR 设备与已知长度的被测光纤（验证级联路径）；
- 测试记录模板：命令、原始回包、耗时、光功率、环境温度、设备 SN、固件版本。

### 9.3 数据管理

- 原始串口日志与长时间采集数据不入库；按 `docs/data-assets.md` 登记字节数、SHA256、采集参数。
- 小体积、可复现的命令/回包样例放 `tests/fixtures/ocs/`。
- 测试结论回写本文与 `docs/detection/README.md` 的 TBD 表；不确定的不要写成确定值。
