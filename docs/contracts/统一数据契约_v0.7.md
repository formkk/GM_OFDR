# 统一数据契约 v0.7

> 目的：让同一套上位机（GM-IX UI）通过选择不同设备接入端，同时承载「联讯整机」与「昊衡 LGA50-D」两类设备。
> 范围：**只定义 L1 单帧曲线**。测量记录（组、参数、标定、平均）与派生结果（峰表、事件、IL/RL、判定）不由契约定义。
> 状态：**v0.7 已冻结**（2026-11-11 落盘前终审通过：四层审查 + 机械检查 PASS 7 + 数据侧契约测试全绿）。冻结后任何字段增删或语义变更须升 v0.8 并重走 §8 评审；未决项 T-01~T-06 只涉及标定取值，不影响结构。

## 1. 分层与术语

### 1.1 分层

| 层 | 内容 | 产生方 | 是否进契约 |
|---|---|---|---|
| **L1 帧** | 轴 + dB 数组 + 帧元数据 | 设备接入端（采集进程 / 导入工具） | 是 |
| **测量记录** | 一次测量的组织：组标识、参数快照、标定快照、平均设定 | 上位机存储层 | **否**（受 §3.4 原则与 §3.5 无损往返约束） |
| **派生层** | 峰表、事件、IL/RL、精度、合格判定 | 指标层自算 | 否 |

### 1.2 术语

| 术语 | 含义 |
|---|---|
| **接入端**（适配器） | 与设备或文件打交道、把原始输出归一成 `CurveScan` 的那一层。产品线中它是 `Gmix.Acquirer` 采集进程或离线导入工具，不是独立组件。 |
| **帧时刻** | 接入端确认该帧数据完整可用的时刻，定义见 G-04。 |
| **功率域 dB** | 10·log10 功率，定义见 C-01。 |
| **测量记录** | 一次测量的组织单位（组、参数、标定、平均），结构不属契约，受 §3.4 原则与 §3.5 无损往返约束。 |
| **派生层** | 峰表、事件、IL/RL、精度、合格判定等下游计算结果。 |

## 2. 帧定义（L1：CurveScan）

### 2.1 结构

```text
CurveScan
├─ Axis
│  ├─ Start  : double      // 索引 0 的物理坐标（米）
│  ├─ Step   : double      // 相邻点间隔（米）
│  └─ Count  : int
├─ Values    : double[]    // 纵轴，dB（语义见 C-01）
└─ Metadata
   ├─ ScanId     : string   // 格式见 G-01
   ├─ SourceType : Lianxun | HengLga50
   └─ DeviceId   : string
```

**数据本体 = 轴描述 + dB 数组；元数据 = 来源、设备、标识。** 轴描述是数据的一半，不是"关于数据的信息"——没有它，数组只是一串无坐标的数。

采集配置与标定快照**不属于帧**，它们属测量记录（§3.4）。

### 2.2 字段语义

| 字段 | 语义 | 约束 |
|---|---|---|
| `Axis.Start` | 索引 0 的物理坐标（米） | 已含零点偏移，下游不得再补偿（C-10） |
| `Axis.Step` | 相邻点间隔（米） | 逐帧携带，禁止全局配置（L-04） |
| `Axis.Count` | 曲线点数 | 必须等于 `Values.Length`（L-01、L-02） |
| `Values` | 纵轴数值 | 功率域 dB（C-01），禁止插值（L-01） |

`Axis.End = Start + Step × (Count − 1)` 是派生值，不是字段（L-08）。

**`Metadata` 字段**（逐帧、全部必填）

| 字段 | 语义 | 约束 |
|---|---|---|
| `ScanId` | 帧标识，同时承载时间与顺序 | 格式固定（G-01）；唯一（G-02）；构造即定型（G-03） |
| `SourceType` | 设备来源 | `Lianxun` / `HengLga50`；决定记录层按哪套设备口径解释参数与标定 |
| `DeviceId` | 设备台号 | 逐台稳定唯一（序列号或等价标识）；不得用 IP 之类会变的量 |

### 2.3 构造前提

构造帧之前必须满足 L-01、L-02、L-03、G-01；不满足则不构造帧，按 §3.6 上报。

## 3. 规则条款（唯一事实源）

条款分六组：标识 **G**、帧结构 **L**、数值语义 **C**、记录层 **R**、落盘与回放 **D**、错误通道 **E**。编号在本版内稳定，不随章节重排变化。

### 3.1 标识 G-01~G-05

| 编号 | 条款 | 违反后果 |
|---|---|---|
| **G-01** | `ScanId` 格式固定为 `yyyyMMdd'T'HHmmss'.'fff'Z'-'NNN`：UTC、定宽（毫秒三位 + `Z`）；尾数 `000`–`999`，同一毫秒内递增、跨毫秒重置。解析正则 `^(\d{8})T(\d{6})\.(\d{3})Z-(\d{3})$` | 不符合不得构造帧 |
| **G-02** | 同一接入端在一次连续出帧会话内不得重复 | 重复即数据损坏 |
| **G-03** | 由接入端构造帧时生成，构造即定型，下游不得改写 | — |
| **G-04** | 帧时刻 = 接入端**确认该帧数据完整可用**的时刻（联讯为到达时刻，昊衡导入为解析完成时刻）；不要求与设备内部时钟一致 | 禁止用记录 ID 或设备时钟反推帧时刻 |
| **G-05** | 是否重放属记录层属性，不改变 `SourceType` | 重放时不得改写来源 |

### 3.2 帧结构 L-01~L-08

| 编号 | 条款 | 违反后果 |
|---|---|---|
| **L-01** | `Values.Length == Axis.Count` 是构造前提；等步距由轴描述给出，禁止插值 | 不构造帧 |
| **L-02** | `Axis.Step > 0` 且 `Axis.Count > 0` 是构造前提 | 不构造帧 |
| **L-03** | `Values` 中出现 `NaN` / `Inf` 时不得构造帧，禁止静默替换为 0 | 不构造帧 |
| **L-04** | 轴只由接入端产生，下游禁止重算、禁止自行推算步距 | 视为契约违约 |
| **L-05** | 帧构造后不可变：`Values` 与元数据只读，需要变换时复制出新数组 | 就地修改视为数据污染 |
| **L-06** | 单帧不携带基线 | — |
| **L-07** | 下游收到帧即视为已通过完整性校验，不重复校验、不携带状态字段 | — |
| **L-08** | `Axis.End` 是派生值，不是字段：不落盘、不参与比较、不进入构造参数 | — |

### 3.3 数值语义 C-01~C-11

| 编号 | 条款 | 违反后果 |
|---|---|---|
| **C-01** | 所有 `Values` 为 **dB 相对功率电平**，数值域是 **10·log10 功率** | 数值域错误即契约违约 |
| **C-02** | 到统一数值域的换算由接入端负责；换算规则须写入该设备的协议说明。幅度代表量取 20·log10 即等价（联讯 `ps = √(|P|²+|S|²)`，已由 T-07 实测闭环）；**已属功率域的值不得再乘 2** | 出现 2 倍偏差 |
| **C-03** | 0 dB 参考点由设备内部决定，契约不表达 | — |
| **C-04** | 差值运算（IL、台阶、峰突出度）安全：参考基准在相减中抵消 | — |
| **C-05** | 绝对性由标定状态决定，不由设备决定：存在有效标定锚点才具备绝对意义 | 无锚点输出绝对量即违约 |
| **C-06** | 数值本身从不因"绝对 / 相对"而换算，变的只是语义与显示后缀 | — |
| **C-07** | 跨设备的绝对值不可比：标定锚点相互独立，即使都具备绝对意义也不得并排为同一刻度 | — |
| **C-08** | 横轴恒为距离、单位恒为米；落盘、传输、计算一律用米；UI 换单位属格式化，不得回流数据 | — |
| **C-09** | 不承载频域曲线；若将来需要，必须升契约版本并重新引入轴类型与单位，历史数据须带版本标识 | — |
| **C-10** | 零点偏移折进 `Axis.Start`，下游不再做任何补偿 | 重复补偿导致系统性偏移 |
| **C-11** | 绝对基准、基线等**能力**由接入端决定，不新增运行时能力字段 | — |

### 3.4 测量记录 R-01~R-05

测量记录的结构由上位机存储层定义，契约只施加以下五条原则。

| 编号 | 条款 | 说明 |
|---|---|---|
| **R-01** | 参数与标定必须分离 | 前者是"这次怎么采的"，后者是"数值怎么变成绝对量"；点距、零点属标定参数，不得与采集参数混放 |
| **R-02** | 快照不可变，且记录设定值 | 记录保存测量开始时的设定值；帧携带生效值，两者允许不同；轴参数以帧内 `Axis` 为准（联讯步距跨帧变化约 15%） |
| **R-03** | 平均是测量方式，不是数据形态 | 单次与 N 次平均的帧结构完全相同；平均次数属采集参数；**进入契约的数值不得是 dB 算术平均的产物**（会压低噪声底、削平峰值），需要平均须在功率域聚合 |
| **R-04** | 每条帧必须能定位到一条可追溯的测量记录 | 该记录至少能回答：用什么参数采的、用哪套标定、当时是否具备绝对性 |
| **R-05** | 每条测量记录必须携带契约版本且可追溯 | 不得只靠文件名或时间戳推断；存放位置由应用层决定 |

### 3.5 落盘与回放 D-01~D-04

落盘格式（文件格式、目录结构、命名规则）属应用层实现细节，不进契约；但落盘数据会作为数据源重新进入契约流转，因此受无损往返约束。

| 编号 | 条款 | 说明 |
|---|---|---|
| **D-01** | 落盘帧读回后必须能重构出满足 §3.1~§3.3 的帧 | 记录层字段（参数、标定、组标识、契约版本）由应用层完整保留 |
| **D-02** | 禁止有损落盘 | 不得单位换算（m → µm）、精度截断（double → float）、字段丢弃（如省 `ScanId`、`SourceType`） |
| **D-03** | 重放不改写来源 | 离线回放的帧 `SourceType` 仍为原始设备来源；是否重放由记录层标注（G-05） |
| **D-04** | 重放端判定职责与在线端相同 | 按 §3.6 执行，走同一套丢弃计数与诊断日志，不另设错误路径 |

目录不需要按 `SourceType` 分区：来源已随记录落盘，读回时自解析；混放不构成违约，分区属应用层排版偏好。

### 3.6 错误通道 E-01~E-04

完整性判定由接入端在构造帧之前完成，结果不作为字段存放。

| 判定 | 错误分类 | 处理 |
|---|---|---|
| 超时内无帧 | 超时 | 不产出帧，写诊断日志（无帧可计） |
| 点数 ≠ 数组长度 | 数据 | 丢弃该帧，计数 + 诊断日志 |
| 数值含 `NaN` / `Inf` | 数据 | 同上 |
| 步距 ≤ 0 / 点数 ≤ 0 | 数据 | 不产出帧，计数 + 诊断日志 |

| 编号 | 条款 | 说明 |
|---|---|---|
| **E-01** | 失败帧不进入契约 | 细节（时刻、期望点数、实收点数、丢弃原因）只写诊断日志 |
| **E-02** | 错误须分类上报：连接 / 协议 / 数据 / 超时 | 连接类错误发生在会话建立阶段，不属帧构造判定；帧构造阶段只涉及协议、数据、超时三类；禁止 `catch {}` 静默吞掉 |
| **E-03** | 不得以零值帧、上一帧替代失败帧，也不得截断补齐后强行构造 | — |
| **E-04** | 丢弃计数只针对"收到了但不可用"的帧 | 无帧不计数 |

## 4. 两类设备的填充对照

**契约字段**

| 字段 | 联讯整机 | 昊衡 LGA50-D |
|---|---|---|
| `Axis.Start` | 0.0 | 0.0（零点偏移待 T-03 标定，当前按 0） |
| `Axis.Step` | 逐帧取 `dist[n+1]−dist[n]`（实测 0.00042~0.00049 m） | 0.000185 m（逐帧相同，待 T-02 复核） |
| `Axis.Count` | 200001（50 MHz / 8 ms 配置下） | 82153 |
| `Values` | dB（相对，未经标定不得视为绝对量） | dB（相对） |

> 实测依据：联讯 `dist.f64` 单帧内相邻步距逐位一致、跨帧变化约 15%，故步距必须逐帧携带；昊衡点距是设备常量，同样逐帧携带，只是数值相同。

**记录层内容（非契约字段，仅供实现参考）**

| 项 | 联讯整机 | 昊衡 LGA50-D |
|---|---|---|
| 采集参数 | 采样率、采集时长、触发模式、延时 | 模式、起点、回损点、窗口 |
| 标定参数 | `rlOffsetK`、`ilSlope`、`ilIntercept`、`psdRef` | 点距、零点偏移（IL 斜率待标定） |

**显示锚点（实现约定，非契约字段）**

- 联讯未标定时，UI 可用固定显示锚点（GM-IX 当前取 -192，对应其 SRS DS-06）把刻度平移到厂商负区间；该锚点**只作用于显示**——不写回数据、不参与合格判定、不得作为测得值导出，且必须同屏标注「未标定」（C-05、C-06）。
- 联讯已标定时，`rlOffsetK` 取自该设备的标定配置（GM-IX 实现为 `calibration.json`）。
- 昊衡当前无锚点，一律按相对 dB 显示并标注「未标定」。

## 5. 与既有实现的关系

本契约面向 **GM-IX（联讯整机上位机）→ LGA50（新增设备线）** 这条正式继承链：GM-IX 的 UI、指标与存储保持不动，新设备以接入方式扩展；统一的是**数据形态**，不是采集实现。

| 实现 | 与契约的关系 | 说明 |
|---|---|---|
| **GM-IX**（正式） | 契约的目标载体 | 现行文件型组存储（`scan.json` + `dist/ps/ps_db`）承载 L1 数值与测量记录元数据；接入 LGA50 时不改 UI |
| **LGA50 接入**（正式，**待实施**） | 契约的第二个来源 | 昊衡设备侧产出按本文归一后进入同一形态；当前仅以 `Gmix.Import` 验证数据侧 |
| `ofdr_platform`（预研） | **仅作参照，不构成约束** | 其 `StandardScan` 曾在预研期按本契约收缩字段，用于验证契约可行性；预研代码独立演进，字段不必与本文同步 |
| `Gmix.Import`（过渡工具） | 数据侧验证 | 把昊衡抓包直接转成 GM-IX 组目录，用于验证"同一 UI 能承载异源数据"；不经过契约对象 |

由此产生三条边界：

1. **不以预研代码为基线**：不要求 `ofdr_platform` 对齐，也不从它的实现反推字段；
2. **不为迁移而兼容**：契约字段与 GM-IX 现有 `scan.json` 是两种表示，落地时由接入层转换，不要求同名同形；
3. **契约先行、实现分批**：L1 已定稿；测量记录结构由各上位机存储层定义（GM-IX 的 `group.json` / `scan.json` 即其实现），契约只施加 §3.4。

**与 GM-IX 规范的优先级**：产品内部的处理链路、落盘 schema 与指标口径，以《GM-IX 数据与处理规范 v1.0》（[`docs/contracts/GM-IX_数据与处理规范_v1.0.md`](GM-IX_数据与处理规范_v1.0.md)）为准；本文只约束**接入层的输入形态**，不重复定义落盘与处理。两者交界只有一处：接入层把帧写入测量记录。凡涉及"存什么、怎么算"，读 GM-IX 规范；凡涉及"不同设备进来必须长什么样"，读本文。

## 6. 决策记录

| ID | 决策 | 理由 | 代价 |
|---|---|---|---|
| ADR-01 | 契约只定义帧，不定义测量记录 | 设备侧没有组概念（LGA50-D 无组命令、无帧号、`STOP` 后仍有在途帧）；参数集无法跨设备统一；GM-IX 已有更宽的记录 schema | 记录结构各端自定，跨端可追溯性只能靠 R-04 约束 |
| ADR-02 | 时间与序号合并进 `ScanId` | 减少两个字段；定宽 UTC 使字典序即时间序 | 必须约束 ID 格式（G-01），且与 GM-IX「不解析 ID」的既有规则冲突，靠接入层隔离 |
| ADR-03 | 删除 `ChannelIn` / `ChannelOut` / `Epoch` | 两台设备均为单光路、无光开关与矩阵切换，三字段恒为常量 | 将来若出现多路切换，需升版加回 |
| ADR-04 | `SourceType` 只表达设备来源，删除 `Replay` | 帧的职责是解释数值与参数，路径信息不属于帧 | 是否重放需由记录层自行标注 |
| ADR-05 | 契约作为设计依据，不落成 GM-IX 代码接口 | `Gmix.Acquirer` 是独立进程，内存类型过不了进程边界；GM-IX 存储 schema 比契约更宽且是继承资产 | 统一性没有编译期保证，只能靠契约测试 |

| T-04 | 昊衡 IL 斜率/截距的两点标定 | IL 绝对值 |
| T-05 | 昊衡远程服务稳定性、是否支持多客户端 | 采集可靠性 |
| T-06 | 曲线值的显示与导出后缀口径（绝对电平用 dBm、相对量用 dB），以及「RL」与「曲线电平」的术语区分 | 显示 / 导出 |

**已闭环：T-07**（联讯 `ps` 量纲判定）——用合成信号对 `ofdr.dll` 做标度律实验（P/S 单变量缩放 + 双音比 + 非对称确认），实测 `ps = √(|P|²+|S|²)`，为两偏振通道总功率的平方根（幅度代表量，内部为 Hann 窗 FFT 后两通道功率相加开方）。因此 `20·log10(ps)` 即 10·log10 功率域 dB（C-02）；与昊衡 `10·log10(Σ10^(v/10))` 同域，两设备 `Values` 数值语义一致。证据：`devices/lga50/tools/t07_ps_dimension.py`（标度律）、`t07_confirm_rss.py`（RSS 确认，三组预测全部精确命中）。

### 8.2 机械检查

3. **计数一致**：章节标题里 `G-01~G-05` 一类的范围与实际条目数相等；
