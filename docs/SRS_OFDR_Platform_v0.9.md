## 1. 引言

### 1.1 目的

定义 OFDR 测试平台软件的功能、接口、数据与非功能需求，作为架构设计、开发、测试与验收的基线。

### 1.2 系统边界（关键）

平台软件只负责“编排 + 标准化 + 计算 + 持久化”，**不负责硬件驱动、固件与光学设计**。硬件通过适配器接入。

| 在范围内 | 不在范围内 |
| --- | --- |
| 采集板（FPGA）/整机的调用适配与错误映射 | 板卡固件、FPGA 逻辑与驱动开发 |
| 由 P/S/A 原始信号到联合功率谱的调用编排 | 光学链路、扫频光源设计 |
| 标准扫描数据模型与校验、序列化 | 长距 OTDR、相干传输测试 |
| 峰值检测、IL/RL/长度/光程计算 | 云端多租户、远程运维平台 |
| 光开关/矩阵等仪表的控制编排 | 仪表固件与硬件改造 |
| 测试流程状态机、结果判定、数据落盘 | MES/数据库的具体实现（仅预留接口） |
| 离线回放、合成数据、无硬件运行 | — |

### 1.3 术语与单位

| 术语 | 定义 |
| --- | --- |
| P/S/A | OFDR 采集的三路信号（P 路、S 路、辅助通道） |
| 联合功率谱 ps | `ofdr.dll` 输出，线性幅值，与 `dist/freq` 等长 |
| StandardScan | 平台唯一跨层数据契约：轴 + 数值 + 单位 + 元数据 |
| 标记点 | A/B/BB/CC/C/D/E，由峰值序列按规则定位，单位“行” |
| 行距 | 标准扫描数据相邻点对应距离，当前 demo 取 0.0002 m/行 |
| IL | 插入损耗，dB；口径为往返功率差的一半（算式与实现位置见 SDD §6.4） |
| RL | 回波损耗，dBm；口径为区间 mW 求和后转 dBm（实现见 SDD §6.4） |
| 代次（Epoch） | 通道切换后的扫描批次标识，用于丢弃残留帧 |
| 距离域事件 | 过阈峰在距离轴上的位置、回损、与上一事件之间的段插损、累积插损与宽度；仅用于界面查看，不落盘 |
| 包络降采样 | 按显示宽度分桶取 min/max，把逐点谱压缩到屏幕像素而不丢失窄峰 |

单位约束：距离 m、频率 Hz、原始样本 int16/LSB、功率谱线性幅值（无量纲）、功率 dBm、损耗 dB。**单位换算只允许在文档 §6.4 指定位置发生一次**。

## 2. 总体描述

### 2.1 产品定位

按架构图四层组织：**数据采集 → 数据处理 → OFDR 标准扫描数据获取（标准化）→ 测试控制与结果计算**。平台以 `StandardScan` 为枢轴，左右两侧（整机 TCP、FPGA 采集板）分别为可替换的采集适配器，上方为可复用的测试编排与指标计算。

### 2.2 用户与角色

| 角色 | 关切 |
| --- | --- |
| 产线操作员 | 一键测试、通道进度、合格判定、异常提示 |
| 调试/工艺工程师 | 参数配置、校准、单通道复测、日志与原始数据 |
| 算法工程师 | 离线回放、合成谱、指标结果对比 |
| 集成开发 | 新增硬件适配器、MES/数据库对接 |

### 2.3 运行环境

- 客户端：Windows 10/11 x64；具备网口。
- 一期硬件选项：仅“整机 TCP”（默认 `192.168.3.111:4300`）。二期采集侧为独立的 FPGA 开发板或定制板，通过网络连接；具体形态、网络协议与帧格式未定（TBD-15），一期不实现。
- 仪表：一期无真实串口接入；光开关/矩阵需按“与真实设备同格式的命令”驱动，可用模拟实现替代，真实串口适配器列为后续工作。
- 交付形态：一期发行包只含平台自身程序与运行库，**不含任何厂商二进制**（处理库、参考结果库等；采集板固件不在 PC 发行包内）。具体依赖清单、运行库版本与启动自检项属设计内容（见 SDD §1.2、§9）。

### 2.4 约束

| ID | 约束 | 来源 |
| --- | --- | --- |
| CON-01 | 厂商库（处理库、参考结果库，以及采集板可能提供的 SDK）均为无源码二进制，只能通过已声明接口调用 | [OFDR][DET][TBD-15] |
| CON-02 | `ofdr`/`detect` 的结果结构由库分配，调用后必须 `*_result_free`，否则内存泄漏；采集板 SDK（若采用）由调用方提供缓冲区 | [OFDR][DET][TBD-15] |
| CON-03 | 采集板原始数据帧格式以最终固件协议为准；暂按 int16 小端、多通道按帧交织（源自旧采集卡资料） | [TBD-15][QT] |
| CON-04 | 整机帧以 `!` 结束，当前按 ASCII 行解析；协议无正式文档 | [DEMO][TBD] |
| CON-05 | 平台为 x64 单进程应用，不引入微服务 | [决策] |
| CON-06 | 现状参数存在两个定义源（`config.txt` 与代码默认值），且可被 GUI 运行期覆盖，导致最终生效值不确定，平台必须收敛 | [DEMO] |
| CON-07 | 一期以“测量闭环可演示”为目标：整机 TCP 为唯一采集路径，离线合成/回放同接口共存 | [决策] |
| CON-08 | 一期不引入需额外分发或安装的第三方依赖（含串口组件），真实串口适配器延后 | [决策] |

### 2.5 假设

- AS-01 同一时刻只操作一台采集设备（多卡并行不在一期范围）。[决策]
- AS-02 被测 DUT 的合格判据（如“恰好 8 峰”）属于业务配置，不是平台通用规则。[决策]
- AS-03 平台可在无硬件条件下以回放/合成数据完整运行。[决策]
- AS-04 厂商 DLL 可在同一进程内被多次初始化/释放（待验证）。[TBD]

## 6. 数据需求

### 6.1 数据字典（平台契约）

| 结构 | 关键字段 | 约束 |
| --- | --- | --- |
| `ScanRequest` | 请求 ID、IN/OUT 通道、采样率、点数/扫描长度、分辨率、触发模式、触发延时、段数、上传范围、校准 ID | 通道 1~8；采样率取 50/100/250/500/1000/2500 MHz（现状档位） |
| `RawScanFrame` | 请求 ID、段序号、P/S/A 样本、样本数、采样率、触发时间戳、设备与 SDK 版本、代次 | 三路等长；int16→float64 的缩放系数显式 |
| `StandardScan` | 扫描 ID、序号、轴（类型/起点/步距/单位）、数值数组、单位、质量标记、元数据、schema 版本、校验和 | 轴严格单调；点数与数值长度一致 |
| `MeasurementResult` | 扫描 ID、标记点、6 项指标、光程、链路长度、峰数、配置快照 ID、状态/错误 | 无效时状态明确，禁止用 0 代替 |
| `DistanceEvent` | 行号、距离、峰回损、宽度、段插损、累积插损 | UI 派生视图；事件数不受 8 峰约束；首事件段插损/累积为 NaN；不落盘 |

### 6.2 单位与量纲

- 距离 m、步距 m/点；频率 Hz；原始样本 int16（LSB）；功率谱线性幅值；功率 dBm；损耗 dB。
- dB 转换、功率归一化、基准修正的位置必须在 SDD 中唯一指定。

### 6.3 数据留存

| 类型 | 内容 | 留存策略 |
| --- | --- | --- |
| 原始数据 | 原始帧（可回放） | 按测试批次；留存粒度、配额、保留期与清理规则见 FR-DATA-07~10（实现见 SDD §14） |
| 标准扫描 | 轴 + 数值 + 元数据 | 可选，用于复算与追溯 |
| 结果 | 每通道聚合与逐帧结果 | 长期（CSV/数据库，待定） |
| 事件（距离域） | 事件位置/回损/段插损/累积/宽度 | 仅内存视图，随下一帧刷新；不落盘 |
| 日志 | 分级日志 | 轮转 + 容量上限（现状单次已达 55.9 MB，不可沿用） |

### 6.4 现状基线（用于回归，不作为目标值）

- 整机帧约 800 KB、约 70 ms 一帧；每行一个 dBm 数值；行距 0.0002 m。
- 实测单帧 806,190 字节 / 80,619 数据行，8 个峰；标记点 A/B/BB/CC/C/D/E。
- 64 通道组合；每通道采样数可配；单通道超时默认 10000 ms。
- 结果文件：`ofdr_raw_*.dat`、`ofdr_lines_*.txt`、`ofdr_metrics_*.csv`、`ofdr_badpeaks_*.txt`。
- **历史 run 实际留存**：`logs/` 下仅有 `ofdr_log_20260909_094043.txt`（58.6 MB）与 `ofdr_metrics_20260909_094043.csv`（3.37 MB），**没有 raw/lines 全谱文件**。因此历史上无法用该 run 反算 IL/RL；一期回归采用“结果级基准数据（CSV 表头与字段）+ 合成谱手算基准”，详见 §8.2。
- 该 run 实际参数：阈值 -77.5 dBm、A=27500 行、D=62500 行、半窗 2000 行（窗口 80 cm）、`WindowWidthCm=2`；与 `config.txt` 的 -85 / A=2500 / D=32500 / 半窗 250 不一致。两套取值不一致属 CON-06 现状缺陷，平台必须收敛为单一快照来源，收敛方式与默认值见 SDD §8.1。
