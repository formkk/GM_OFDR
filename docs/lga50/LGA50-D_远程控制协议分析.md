# LGA50-D 远程控制协议分析（厂商资料 + 实测）

- 版本：v0.1
- 日期：2026-11-09
- 依据：`ref/LGA50-D远程控制说明.pdf`（6 页）与实测抓包
- 实测对象：`192.168.2.26:4300`（Windows，NetBIOS 名 `DESKTOP-3KOSF0O`）
- 抓包与工具：`LGA50/capture/`、`LGA50/tools/`

## 1 资料与设备现状

厂商资料只有一个 PDF，无 SDK、无头文件、无示例代码、无数据样例，协议细节必须靠实测补齐。

设备侧前置条件（已踩坑）：

1. 远程控制必须在 LGA50-D 软件里手工开启（`功能 → 远程控制 → 打开`，或 `自动远程控制-打开`），默认是关闭；PDF 明确写"一段时间不连接后远程连接状态会自动关闭"。
2. 开启前 4300 不监听，但主机本身在线（135/139/445 开放），所以排查顺序是：先确认主机可达 → 再确认 4300 监听。
3. 本机 `192.168.2.21` 是群晖 NAS（DSM 5000/5001），不是设备，勿混淆。
4. PDF 默认 IP 为 `192.168.1.1/24`，现场实际为 `192.168.2.26`，说明 IP 可改，配置项未文档化。

## 2 会话行为

| 行为 | 实测结果 |
|---|---|
| 传输层 | 纯 TCP，无 TLS、无认证 |
| 握手 | 建连后服务端立即发 `OSI`（3 字节，**无任何结束符/换行**） |
| 指令编码 | ASCII 原文，**无换行、无结束符** |
| 回执编码 | 同样是裸字符串，无分隔符，只能靠内容识别（`SETOK` / `ERROR` / 纯数字） |
| 扫描中建连 | 未发任何指令就会被灌数据（原始模式约 14 MB/s） |
| 断开连接 | **不会停止扫描**，下次建连继续被灌 |
| `QUIT` | 服务端直接关闭连接，无回执；可立即重连 |
| 参数持久化 | 模式/起点/回损点/窗口/RAW 开关/延时在服务端持久化，**跨连接生效** |
| 并发 | 未验证（TBD-08） |

## 3 指令表（实测回执）

| 指令 | 文档写的回执 | 实测回执 | 结论 |
|---|---|---|---|
| `START` | 数据 | 数据流 | 连续扫描，直到 `STOP` |
| `STOP` | 无 | 无 | 停止后仍有 1~2 帧在途（已缓冲） |
| `DELAY_100` | 未写 | `SETOK` | **实测无效**，见 §5.4 |
| `FIBER_START_x.xxx` | `SETOK`/`ERROR` | `SETOK` | 3 位小数，见 §5.1 |
| `RT_LOCATION_x.xx` | `SETOK`/`ERROR` | `SETOK` | 2 位小数，见 §5.2 |
| `WIN_LEN_x.xx` | `SETOK`/`ERROR` | `SETOK` | 2 位小数，见 §5.2 |
| `AUTO_REMOTE_ON` | `SETOK`/`ERROR` | 未测 | 会改变软件常驻状态，未做破坏性验证 |
| `AUTO_REMOTE_OFF` | `SETOK`/`ERROR` | 未测 | 同上 |
| `RAW_DATA_ON` | 数据帧 | `SETOK` + 数据帧 | 见 §4.1 |
| `RAW_DATA_OFF` | 数据帧 | `SETOK` + 数据帧 | 见 §4.2 |
| `LENGTH` | 数字 | `82153`（5 字节，无结束符） | 当前原始点数 |
| `MODE_1` / `MODE_2` | 未写 | `SETOK` | **实测无任何可观测影响**，见 §5.3 |
| `QUIT` | 断开 | 无回执，连接关闭 | — |

`LENGTH` 在 `MODE_1`、`MODE_2`、`RAW_DATA_ON`、`RAW_DATA_OFF` 下均返回 `82153`，即点数与模式、回传类型都无关。

## 4 数据帧格式（实测，与文档不同）

### 4.1 原始曲线帧（`RAW_DATA_ON`）

- 有效点数 **82153**（与 `LENGTH` 一致）
- 每个值：`%9.2f`（右对齐 9 字符）+ `\n`，共 **10 字节**
- 帧内最后一个值的行尾是 **`\r` 而不是 `\n`**，随后紧跟帧尾 `!`
- 单帧长度 = `82153 × 10 − 1 + 1 + 1` = **821531 字节**（值区 821530 + `!` 1）

实测字节（帧首）：

```
20 20 20 2D 37 35 2E 35 39 0A    "   -75.59\n"
20 20 20 2D 37 36 2E 36 33 0A    "   -76.63\n"
```

实测字节（帧尾）：

```
2D 31 32 36 2E 35 33 0A  2D 31 32 38 2E 37 30 0A  2D 31 32 34 2E 32 30 0D 21
"-126.53\n"            "-128.70\n"            "  -124.20\r"      "!"
```

解析要点：

1. **必须以 `!` 定位帧边界**，不能按固定字节数硬切：首帧前面还粘着 `OSI` 和 `SETOK`。
2. 帧体内按 `\n` 切分、再剔除 `\r`，即可得到 82153 个浮点数；末值以 `\r` 结尾属于正常现象，不是脏数据。
3. 值本身是 dB 量级的相对电平（实测 -75 ~ -130），**不是 dBm，也不是标定后的绝对回损**。

### 4.2 结果帧（`RAW_DATA_OFF`）

- 固定 **25 字节** = `%11.6f\n`（12） + `%11.6f\r`（12） + `!`（1）
- 第 1 个值：光纤长度，单位 m，6 位小数
- 第 2 个值：回损值，单位 dB，6 位小数（负值）

实测：

```
b"   1.104190\n -85.424156\r!"
```

实测样本：长度 `1.104190 m`，回损 `-85.42 dB`。

## 5 参数语义实测

### 5.1 光纤起点（`FIBER_START`）

| 起点设置 | 回传长度 | 说明 |
|---|---|---|
| 0.000 | 0.002035 | 特例，返回首个反射峰位置 |
| 0.001 | 0.003625 | 同上，仍落在首个反射峰上 |
| 0.100 | 2.004190 | 正常 |
| 1.000 | 1.104190 | 正常 |
| 2.104 | 1.31 ~ 4.34 跳变 | 起点等于末端，结果无意义 |
| 2.500 | 0.22 ~ 1.58 跳变 | 起点超过末端，结果无意义 |
| 3.000 | 3.08 ~ 0.36 跳变 | 同上 |

结论：

- 正常区间内满足 **长度 = 末端位置 − 起点**，当前链路末端位置实测 **2.104190 m**。
- 2.104190 是当前接线/采集下的末端位置，**不是固定常量**，会随采集变化。
- 起点过小（≤ 约 0.01 m）时返回首个反射峰位置（0.002~0.004 m），语义完全不同。
- 起点 ≥ 末端位置时输出跳变，**必须在应用层钳制起点范围**。

### 5.2 回损点与窗口（`RT_LOCATION` / `WIN_LEN`）

固定起点 0.000：

| 回损点 m | 窗口 m | 回损 dB |
|---|---|---|
| 0.50 | 1.00 | -67.7 |
| 1.10 | 1.00 | -86.2 |
| 2.11 | 0.10 | -94.9 |
| 2.11 | 0.50 | -88.2 |
| 2.11 | 2.00 | -82.4 |

结论：

- 窗口越宽，回损越接近 0（数值越大），说明**不是取单点，而是窗内某种统计/能量聚合**。
- 回损值（-67 ~ -95 dB）与曲线纵坐标（-75 ~ -130 dB）不是简单对应关系，**不能用曲线最大值直接替代**。
- 窗内具体算法（最大值 / 线性功率积分 / 分位数）未定，见 TBD-03。

### 5.3 测量模式（`MODE_1` / `MODE_2`）

实测两种模式下：

- `LENGTH` 均为 82153；
- 原始帧长度均为 821530 字节；
- 峰位序列完全一致（index 4/25/42/63/75/101/112/131…）；
- 结果帧的长度与回损无差异。

即 **当前固件/配置下 `MODE_1` 与 `MODE_2` 无任何可观测效果**，文档所述 20 µm / 40 µm 点距差异未体现。

### 5.4 扫描间隔（`DELAY_`）

| 设置 | 实测帧率 |
|---|---|
| DELAY_0 | 19.0 帧/秒 |
| DELAY_100 | ~19 帧/秒 |
| DELAY_1000 | 19.2 帧/秒 |
| DELAY_5000 | 18.5 帧/秒 |

结论：`SETOK` 正常但**不生效**。基线帧率约 **17~19 帧/秒**（52~58 ms/帧），与设置无关。

## 6 X 轴换算（已定量）

实测方法：同一台设备分别接标称 1 m 与 2 m 尾纤，读设备自报的"光纤长度"，同时在原始曲线中定位对应的末端反射峰。

| 尾纤 | 末端峰 index | 末端峰电平 | 设备报长度 |
|---|---|---|---|
| 1 m | 5501 | -61.3 dB | 1.017685 m |
| 2 m | 11374 | -109.3 dB | 2.104190 m |

- 峰位比 `11374 / 5501 = 2.06762`，与长度比 `2.104190 / 1.017685 = 2.06762` **完全一致**（5 位小数），说明长度与 index 严格线性。
- 折算点距 = `1.017685 / 5501` = `2.104190 / 11374` = **185.0 µm/点**。
- 整条曲线 x 量程 = `82152 × 185 µm ≈ 15.2 m`。此前"2.104190 m 是轴末端、点距 25.59 µm"的判断**是错误的**：2.104190 m 只是当时那根 2 m 尾纤的末端反射位置，不是量程边界。
- 曲线在末端峰 index 之后即落到噪声底（≈-125 dB），因为已经超出光纤长度，不是量程结束。
- 光程/物理：1 m 尾纤报 1.0177 m；若 X 轴为光程应报约 1.47 m，故 **X 轴是物理距离**。
- 文档的 20/40 µm 与 185 µm 相差 4.6~9 倍，且模式切换无变化，判断该值是采集端采样间隔或其它型号参数，**不能用作本机距离轴**。
- 剩余不确定度：点距绝对值取决于尾纤真实长度（目前仅有标称 1 m / 2 m，±2% 量级）。用尺实测尾纤长度或改用标准件可把误差压到 1% 以内。

结论：程序内距离轴 = `index × 185.0 µm`（必须做成可配置参数），见 TBD-04。文档要求的"零点位置通过不接光纤时的峰值确定"仍成立，用于确定 index 0 的绝对偏移。

## 8 解析实现建议

1. **帧边界只认 `!`**，用滑动缓冲；收到 `!` 前不解码。
2. 会话状态机：`连接 → 读 OSI → 指令/回执态 ↔ 数据流态`；`START` 进入数据流态，`STOP`/`QUIT` 退出。
3. 指令回执按内容匹配：`SETOK` / `ERROR` / 纯数字（`LENGTH`），**没有结束符，必须靠已知回执长度或超时判定**。
4. 原始帧解析：值区按 10 字节步进，末值以 `\r` 结尾；校验 `(帧体长度+1) == 点数×10`。
5. 结果帧解析：严格 25 字节；前 11 字符长度、11~22 字符回损。
6. 连接后**先发 `STOP` 再做事**，避免扫描中的历史数据流干扰回执解析。
7. 应用层需自行打时间戳并做丢帧统计（协议无帧号）。
